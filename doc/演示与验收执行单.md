# 演示与验收执行单

更新时间：2026-03-20  
适用版本：`V3`  
目标：用最少步骤复现“当前版本可演示、可回归、可封版”的结论

## 1. 验收前准备

### 1.1 启动依赖与服务

在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File start-all.ps1
```

确认服务：

- Admin 后端：`http://localhost:8080`
- App 后端：`http://localhost:8081`

### 1.2 重置测试数据

建议每次演示前执行一次：

```powershell
powershell -ExecutionPolicy Bypass -File tests/reset-test-data.ps1
```

### 1.3 启动前端

Admin 前端：

```powershell
cd frontend
npm run dev
```

App 前端：

```powershell
cd frontend-app
npm run dev
```

默认地址：

- Admin：`http://localhost:5173`
- App：`http://localhost:5174`

## 2. 演示账号

- Admin：`root_admin / root`
- App：`root / root`

## 3. 最短验收路径

### 3.1 API 基线

先确认自动回归基线正常：

```powershell
npx newman run tests/fitness-platform-core.postman_collection.json -e tests/local.postman_environment.json
npx newman run tests/fitness-platform-full.postman_collection.json -e tests/local.postman_environment.json
```

通过标准：

- `core`：`39 requests / 143 assertions / 0 failed`
- `full`：`127 requests / 389 assertions / 0 failed`

### 3.2 Admin 浏览器验收

按下面顺序操作：

1. 打开 Admin 登录页
2. 使用 `root_admin / root` 登录
3. 进入“权限中心”
4. 进入“视频素材”，点击“刷新”
5. 进入“订单”，点击任意一条订单查看详情
6. 进入“操作日志”，点击“示例筛选”后再点“查询”

通过标准：

- 登录后能进入受保护页面
- 视频列表能正常刷新
- 订单详情能正常显示
- 操作日志筛选查询能正常返回结果

### 3.3 App 浏览器验收

按下面顺序操作：

1. 打开 App 登录页
2. 使用 `root / root` 登录
3. 首页输入 `site_name,default_avatar`，点击“读取配置”
4. 进入“教练预约”
5. 选择一个可用档期，点击“提交预约”
6. 点击“模拟支付”
7. 点击“确认完成”
8. 点击“填充示例”
9. 点击“提交评价”

通过标准：

- 首页能读到系统配置
- 预约能成功创建
- 支付后状态更新
- 完成后可提交评价

### 3.4 App 课程闭环验收

按下面顺序操作：

1. 进入“课程”
2. 选择一个可报名排期
3. 点击“提交报名”
4. 点击“模拟支付”
5. 输入退款原因
6. 点击“发起退款”

通过标准：

- 报名成功
- 支付成功
- 退款成功

## 4. 当前已经证明的结论

- 后端核心接口主链可用
- 前端核心页面不只是能打开，而且已验证能真实请求后端
- Admin 与 App 的核心业务闭环可演示
- 当前版本适合作为作品集、面试演示和阶段性交付基线

## 5. 当前不纳入本次验收

以下内容不属于这次封版验收的必须项：

- 扩展认证页面
- 支付回调测试页
- 退款审计独立页面
- 支付回调审计独立页面
- 用户角色复杂维护工作台
- 所有异常分支的穷举 UI 测试

## 6. 失败时的处理顺序

如果现场验收失败，按这个顺序排查：

1. 先看 `8080`、`8081` 是否仍在监听
2. 再执行 `tests/reset-test-data.ps1`
3. 再重跑 `core` 回归
4. 最后再重试浏览器主链

## 7. 封版建议

- 当前建议：可以封版
- 当前版本定位：稳定演示基线
- 后续如果继续开发：只允许明确主题的小范围迭代，不再无限扩张
