# 运动健康管理平台工程技术亮点汇总

## 1. 当前已实现功能总览（功能 + 技术亮点）

### 1.1 用户认证与权限
- 功能：注册、登录、刷新令牌、登出、短信验证码。
- 技术亮点：JWT 登录态贯穿 app 接口；Redis 存储短期验证码与令牌相关状态，减少数据库热点读写。

### 1.2 训练计划与订阅
- 功能：计划列表、计划详情、计划订阅。
- 技术亮点：
  - 订阅幂等：同一用户重复订阅走更新语义，不产生脏重复记录。
  - 计划详情视频批量查询：一次查全 `video_id`，避免 N+1 查询。

### 1.3 训练打卡与周统计
- 功能：训练打卡、打卡历史、近7日统计。
- 技术亮点：统计逻辑在服务端聚合，前端直出图表数据，降低前端计算复杂度并提升一致性。

### 1.4 教练预约与订单支付
- 功能：档期查询、创建预约、支付成功回调、授课完成、课后评价。
- 技术亮点：
  - 防超卖：`booked_count < capacity` 原子更新策略，降低并发超卖风险。
  - 双幂等：支付回调使用 Redis 短时幂等 + 数据库幂等键双保险。
  - 超时补偿：定时任务自动关闭超时未支付预约并回滚占用名额。

### 1.5 视频教学（本轮新增）
- 功能：
  - Admin 上传视频到 MinIO
  - 视频素材台账管理（新增/更新/启停）
  - 训练计划项绑定/解绑视频
  - App 计划详情返回动作级视频播放地址
- 技术亮点：
  - 资源域解耦：`training_plan_item.video_id -> video_asset.id`，内容运营与训练业务解耦。
  - 存储分层：元数据在 MySQL，二进制文件在 MinIO。
  - 安全播放：优先返回 MinIO 预签名 URL（限时），失败时降级普通 URL。
  - 上传防护：文件大小和扩展名校验（mp4/mov/webm，<=200MB）。

### 1.6 管理端运营能力
- 功能：用户/角色管理、预约与订单管理、看板汇总。
- 技术亮点：admin 业务接口聚焦运营闭环，避免无价值“表级 CRUD 泛滥”。

## 2. 分层与解耦设计
- `controller`：只做参数接收与结果返回。
- `service/core`：原子能力（单实体规则）。
- `service/biz`：跨实体业务编排（状态流转、幂等、补偿）。
- `mapper`：数据访问。
- `model`：统一实体定义，继承 `BaseEntity` 审计字段。

## 3. 状态机与一致性策略
- 预约状态：`WAIT_PAY -> PAID -> SERVING -> COMPLETED -> CANCELED`
- 订单状态：`INIT -> UNPAID -> PAID -> CLOSED -> REFUNDED`
- 一致性策略：
  - 状态前置校验（禁止非法跳转）
  - 支付回调幂等（重复通知不重复入账）
  - 定时补偿（最终一致）

## 4. 可观测与可演示性
- Knife4j 已按 app/admin 分组配置，可直接在浏览器调试接口。
- 核心链路可演示：登录 -> 订阅计划 -> 打卡 -> 预约支付 -> 完成评价 -> 后台看板/订单。
- 视频链路可演示：上传 -> 建素材 -> 绑定计划项 -> app 播放。

## 5. 当前主要不足（下一步优化）
- 视频仍是“基础上传+播放”，尚未接入转码/截图/审核异步流水线（可接 MQ）。
- 缺少更完整的自动化测试（接口集成测试、并发回归测试）。
- 缺少更细粒度观测指标（如支付回调耗时、超时关单命中率）。
