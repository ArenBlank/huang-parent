# 运动健康管理平台工程技术亮点汇总

## 1. 当前项目定位

- 工程型单体项目
- `web-admin` 单实例 + `web-app` 可双实例部署
- 以 `MySQL + Redis + Caffeine + Nginx` 为核心的一致性与性能优化项目
- 面向中小规模高并发冲突场景的治理型后端项目

## 2. 当前已实现能力

### 2.1 业务闭环

- 训练计划：列表、详情、订阅、计划项绑定视频资源
- 训练记录：打卡、历史记录、周统计
- 课程学习：课程管理、排期、报名、支付、退款、我的报名记录
- 教练预约：档期查询、预约创建、支付、完成、评价
- 运营位：Banner、Notice、SystemConfig
- 管理后台：RBAC 权限、操作日志、支付回调审计、退款审计、任务运行记录

### 2.2 工程能力

- 双实例部署与 Nginx 轮询
- `TokenVersion-enhanced stateless JWT authentication`
- `@RateLimit`、`@IdempotentSubmit` 注解式请求守卫
- `Caffeine + Redis + Redis Pub/Sub` 多级缓存与近实时失效
- 任务中心与补偿任务运行记录
- `traceId + userId + instanceId` 链路可观测
- `Postman/Newman + GitHub Actions` 自动化回归

## 3. 核心架构设计

### 3.1 双实例部署

- `web-admin` 固定单实例，默认端口 `8080`
- `web-app` 支持双实例，默认端口 `8081` / `8082`
- Nginx 通过 `upstream` 轮询转发到多个 `web-app` 实例
- 响应头回传 `X-App-Instance`，便于验证负载均衡命中

### 3.2 无状态认证补强

- App/Admin 统一使用 JWT
- Token claim 中携带：
  - `platform`
  - `type`
  - `tokenVersion`
- 使用 `user.status + token_version` 实现：
  - 账号禁用即时失效
  - 密码重置后旧 token 失效
  - App/Admin refresh token 按平台续签

### 3.3 三层并发治理

- 应用层：
  - `@RateLimit`
  - `@IdempotentSubmit`
- Redis 层：
  - 固定窗口限流
  - 短幂等键
  - 短锁
  - 热点缓存互斥重建
- 数据库层：
  - 事务
  - 条件更新
  - 唯一索引兜底

对应场景：

- 课程报名：幂等 + 限流 + `booked_count < capacity` + 唯一索引
- 教练预约：幂等 + 限流 + 条件更新 + 唯一索引
- 支付回调：Redis 短锁 + 支付状态校验 + 数据库幂等兜底

### 3.4 多级缓存与近实时失效

仅对静态低频数据使用本地缓存：

- Banner
- Notice
- SystemConfig
- Course List
- Plan List
- Plan Detail Static

缓存策略：

- `L1 Caffeine -> L2 Redis -> DB`
- 写路径在事务提交后执行：
  - 删除 Redis
  - 删除当前实例本地缓存
  - 发布 `cache:evict` 消息
- 其他实例订阅 Redis Pub/Sub 后仅删除自己的本地缓存
- 保留 `TTL jitter`、空值缓存、热点互斥重建作为兜底

明确不进入本地缓存的数据：

- 订单详情
- 支付状态
- 退款状态
- 课程排期余量
- 预约状态

### 3.5 运维与补偿

- 新增任务中心接口：
  - `GET /admin/task-run/page`
  - `GET /admin/task-run/summary`
  - `POST /admin/task-run/{taskCode}/trigger`
- 当前接入任务：
  - `PAYMENT_COMPENSATE`
  - `BOOKING_TIMEOUT_CLOSE`
- 任务执行写入 `task_run_log`
- 双实例下通过 Redis 任务锁避免重复执行
