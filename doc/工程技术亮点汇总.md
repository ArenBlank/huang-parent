# 运动健康管理平台工程技术亮点汇总

## 1. 当前已实现能力（可演示）
- 认证与权限：`/app/auth/**` + `/admin/auth/login`，JWT 登录态贯穿。
- 训练计划闭环：计划列表/详情/订阅，计划项支持绑定 `video_asset`。
- 打卡闭环：训练打卡、历史记录、周统计。
- 预约闭环：档期查询 -> 预约 -> 支付回调幂等 -> 授课完成 -> 评价。
- 课程闭环：课程创建/上架/排期 -> 报名 -> 支付 -> 退款 -> 我的报名记录。
- 审计能力：支付回调审计、退款审计可在管理端查询。
- 操作日志：关键写操作落库到 `operation_log`，支持管理端查询。
- 运营位能力：Banner 已打通 Admin 管理与 App 消费链路。
- 公告能力：Notice 已打通 Admin 管理与 App 消费链路。
- 系统参数能力：SystemConfig 已打通 Admin 管理与 App 按key读取链路。
- 自动化：Postman 集合 + 云端 Integration 回归（MySQL/Redis/MinIO + SQL 初始化 + Newman）。
- 细粒度 RBAC：权限码从配置扩展到数据库 `permission/role_permission`，支持动态分配与回归验证。
- 支付验签适配：`PaymentSignVerifier` 抽象 + `mock/hmac` 双实现，便于平滑切换真实支付 SDK。
- 链路可观测：App/Admin 统一 `traceId + userId`，关键链路记录耗时日志（支付回调/报名/退款/预约）。

## 2. 分层与解耦设计
- `controller`：参数校验与响应封装。
- `service/core`：单实体原子能力。
- `service/biz`：跨实体业务编排（状态机、幂等、补偿）。
- `mapper`：数据访问。
- `model`：统一实体与 `BaseEntity` 审计字段。

## 3. 一致性与并发关键点
- 预约/课程防超卖：`booked_count < capacity` 原子更新。
- 支付回调幂等：数据库幂等键 + 状态校验，重复通知不重复入账。
- 超时补偿：定时任务关闭超时未支付单据并回滚占用名额。

## 4. 可观测与可回归
- Knife4j：按 app/admin 分组调试接口。
- Postman：核心业务链路自动化断言。
- GitHub Actions：
  - `CI`：快速编译门禁。
  - `Integration`：中间件临时环境 + 全链路接口回归。
- HMAC 验签回归：新增“签名失败/成功”用例，确保验签逻辑可回归。

## 5. 面试可讲亮点（验签适配）
- 抽象支付验签接口：`PaymentSignVerifier` 统一入口，Mock/HMAC 双实现，后续接入微信/支付宝仅替换实现类。
- 明确签名 payload 规则：`payNo|tradeNo|status|amount`，避免字段顺序/空值导致验签失效。
- 回归覆盖正负例：HMAC 正确签名放行，错误签名拒绝，证明“安全规则可回归”而非一次性手测。
- CI 环境固定密钥演示：在 Integration 中传入 `payment.sign.secret`，保证每次回归稳定可复现。

## 5. V2功能补全清单同步

### 5.1 已实现
- 用户认证与登录态：`user/role/user_role` + app/admin 登录接口。
- 计划与打卡：`training_plan*`、`training_record`、`video_asset` 相关接口闭环。
- 教练预约：`coach_schedule/coach_booking/coach_review` + 订单支付闭环。
- 课程学习：`course/course_schedule/course_enrollment` + 支付退款闭环。
- 审计查询：`payment_callback_log`、`refund_record` 管理端可查。
- 操作日志：`operation_log` 已覆盖课程、视频、教练审核、预约超时处理等关键写操作。
- AOP审计：`@OperationLog` 注解 + 切面自动落库，减少业务代码重复日志调用。
- 运营Banner：`/admin/banner/**` + `/app/banner/list` 已可回归验证。
- 运营Notice：`/admin/notice/**` + `/app/notice/list` 已可回归验证。
- 系统配置：`/admin/system-config/**` + `/app/system-config/map` 已可回归验证。
- 自动化回归：Postman + Integration 已可跑通。

### 5.2 未实现
- 多明细订单能力：`order_item` 存在但未充分用于复杂订单场景。

### 5.3 计划延期（V2 不做）
- 真实第三方支付 SDK（微信/支付宝）接入。
- MQ 生产化异步治理（死信、重试、消费监控）。
- 前端/Nginx 正式部署编排完善。
