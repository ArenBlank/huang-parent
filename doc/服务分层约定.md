# 服务分层约定

## 目标
- 避免“Controller 写业务”和“ServiceImpl 大杂烩”。
- 保持双端模块一致的分层方式，便于扩展与排错。

## 分层规则
- `controller`：参数校验、鉴权入口、返回封装，不写跨表业务。
- `service/biz`：业务编排层，负责状态机、事务边界、跨表流程。
- `service` 与 `service/impl`：原子能力薄层（单表 CRUD 与简单查询）。
- `mapper`：数据访问层，不写业务判断。

## 设计约束
- 状态流转只允许在 `biz` 层触发。
- 跨表写操作必须在 `biz` 层开启事务。
- `controller` 禁止直接调用 `mapper`。
- 需要复用的原子查询，先下沉到 `service/impl`，再由 `biz` 组合。

## 当前落地
- 预约支付、训练计划、打卡链路已统一放在 `service/biz`。
- 登录态由 JWT + `LoginUserHolder` 提供，业务接口不再传 `userId`。
