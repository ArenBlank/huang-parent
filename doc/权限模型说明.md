# 权限模型说明（RBAC）

## 1. 目标
在 Admin 端引入“角色 + 权限码”的最小 RBAC，用于区分运营/审核/超管职责边界。
- 角色决定可用权限集合
- 接口通过 `@RequireAdminPermission` 标注所需权限码
- 运行时优先读取数据库 `permission / role_permission`，为空时回退到 `application.yml`

## 2. 角色说明
- `ADMIN`：超级管理员。
  - `admin.permission.admin-all=true` 时默认放行所有 `@RequireAdminPermission` 接口
- `OPS_ADMIN`：运营管理员，负责内容、课程、视频、系统配置
- `AUDIT_ADMIN`：审核管理员，负责退款/回调/教练申请/操作日志

## 3. 权限码与接口映射
### OPS_ADMIN
- `banner:manage`
  - `POST /admin/banner`
  - `PUT /admin/banner`
  - `PUT /admin/banner/status`
  - `DELETE /admin/banner`
- `notice:manage`
  - `POST /admin/notice`
  - `PUT /admin/notice`
  - `PUT /admin/notice/status`
  - `DELETE /admin/notice`
- `system:config`
  - `POST /admin/system-config`
  - `PUT /admin/system-config`
  - `DELETE /admin/system-config`
- `video:upload`
  - `POST /admin/video/upload`
- `video:asset`
  - `POST /admin/video`
  - `PUT /admin/video`
- `video:status`
  - `PUT /admin/video/status`
- `video:bind`
  - `PUT /admin/video/bind-plan-item`
  - `PUT /admin/video/unbind-plan-item`
- `course:create`
  - `POST /admin/course`
- `course:publish`
  - `PUT /admin/course/{id}/status`
- `course:schedule`
  - `POST /admin/course/schedule`
- `course:update`
  - `PUT /admin/course`
  - `PUT /admin/course/schedule/status`

### AUDIT_ADMIN
- `refund:audit`
  - `GET /admin/refund/list`
- `pay:callback:audit`
  - `GET /admin/pay/callback/list`
- `coach:apply:audit`
  - `GET /admin/coach-apply/list`
  - `GET /admin/coach-apply/{id}`
  - `POST /admin/coach-apply/audit`
- `operation:log:read`
  - `GET /admin/operation-log/list`

## 4. 资源级范围（课程分类）
- `course-category-scope`：按课程分类限制可管理范围
- 仅作用于课程创建/更新/上架/排期
- 若角色未配置范围，则默认不限制
- 支持 `-1` 表示“全部分类”
- 优先读取数据库表 `role_course_category_scope`，为空时回退到 `application.yml` 配置

## 5. 配置入口（可作为默认/兜底）
`web/web-admin/src/main/resources/application.yml`：
```yml
admin:
  permission:
    admin-all: true
    role-map:
      OPS_ADMIN:
        - banner:manage
        - notice:manage
        - course:create
        - course:publish
        - course:schedule
        - course:update
        - video:upload
        - video:asset
        - video:bind
        - video:status
        - system:config
      AUDIT_ADMIN:
        - refund:audit
        - pay:callback:audit
        - coach:apply:audit
        - operation:log:read
    course-category-scope:
      OPS_ADMIN:
        - 1
      # ADMIN:
      #   - -1
```

## 6. 管理接口
- 查询范围：`GET /admin/role/{roleId}/course-category-scope`
- 更新范围：`PUT /admin/role/{roleId}/course-category-scope`
- 批量更新：`PUT /admin/role/course-category-scope/batch`
- 权限清单：`GET /admin/role-permission/permissions`
- 角色权限列表：`GET /admin/role-permission/role/{roleId}/permissions`
- 角色权限分配：`POST /admin/role-permission/assign`

## 7. 返回码约定
- 权限不足时返回业务码 `309`（由 Admin 侧拦截器统一处理）

## 8. 扩展方式
1. 在目标接口方法上增加 `@RequireAdminPermission("xxx:yyy")`
2. 在 `application.yml` 的角色映射中补上对应权限码
3. 如需资源级限制，在 `course-category-scope` 中配置可管理范围
4. 在 Postman 回归集合里补充“允许/拒绝”用例
