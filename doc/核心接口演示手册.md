# 核心接口演示手册

## 演示目标
- 10 分钟内讲清平台核心闭环：登录、预约、支付异步回调、退款、审计可追踪。

## 演示前准备
- 启动 `web-admin(8080)`、`web-app(8081)`。
- 执行数据重置：`powershell -ExecutionPolicy Bypass -File tests/reset-test-data.ps1`
- Postman 环境选择：`fitness-local`。

## 建议演示链路（6 步）
1. `POST /app/auth/login`
2. `POST /app/booking/create`（返回 `bookingId`、`payNo`）
3. `POST /app/pay/mock-notify`（首次，状态推进）
4. `POST /app/pay/mock-notify`（二次，幂等）
5. `POST /app/course/refund`（课程退款）
6. `GET /admin/refund/list` + `GET /admin/pay/callback/list`（退款与回调审计）

## 演示关键讲点
- 档期防超卖：`booked_count < capacity` 原子更新，避免并发超卖。
- 支付幂等：回调重复通知只生效一次，后续进入 `IDEMPOTENT`。
- 状态机联动：支付状态驱动订单与业务单状态一致变更。
- 可追踪：退款审计与支付回调审计都能按条件筛选。

## 建议现场说法
- “我们把支付做成异步回调模型，支持重复通知幂等处理，并把每次通知落审计日志，便于追踪和复盘。”
- “预约和课程排期都用原子更新控制容量，避免超卖。”
- “回归集合 20 条接口已全绿，可重复执行。”
