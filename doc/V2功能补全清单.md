# V2功能补全清单（SQL × 接口对照）

## 目标
- 锁定 V2 范围，避免需求无限扩张。
- 按“表结构 + 接口 + 可回归”三维判断是否真正完成。

## 已实现
- 用户认证与登录态
  - 表：`user`、`role`、`user_role`
  - 接口：`/app/auth/**`、`/admin/auth/login`
  - 状态：已接入 JWT，已纳入 Postman/Integration 回归
- 训练计划与打卡
  - 表：`training_plan`、`training_plan_item`、`training_plan_subscribe`、`training_record`、`video_asset`
  - 接口：`/app/plan/**`、`/app/record/**`、`/admin/video/**`
  - 状态：支持计划订阅、打卡、计划项绑定视频、播放地址校验
- 教练预约闭环（先支付后上课）
  - 表：`coach_schedule`、`coach_booking`、`coach_review`、`order_info`、`payment_record`
  - 接口：`/app/booking/**`、`/app/pay/**`、`/admin/ops/**`
  - 状态：包含回调幂等、超时关单、完成授课与评价
- 课程学习闭环
  - 表：`course`、`course_schedule`、`course_enrollment`、`order_info`、`payment_record`、`refund_record`
  - 接口：`/app/course/**`、`/admin/course/**`、`/admin/refund/list`
  - 状态：课程创建/上架/排期/报名/支付成功/退款/我的报名记录
- 教练申请审核闭环（本次新增）
  - 表：`coach_profile`
  - 接口：`/app/coach/apply`、`/app/coach/my-application`、`/admin/coach-apply/**`
  - 状态：学员提交资料 -> 管理端审核 -> 通过后自动赋予 `COACH` 角色并更新 `user_type=coach`
- 审计可追踪
  - 表：`payment_callback_log`、`refund_record`、`operation_log`
  - 接口：`/admin/pay/callback/list`、`/admin/refund/list`、`/admin/operation-log/list`
  - 状态：管理端可查询回调、退款、关键写操作日志（课程/视频/预约处理/教练审核）；`@OperationLog` + AOP 自动落库已接入
- 运营Banner闭环
  - 表：`banner`
  - 接口：`/admin/banner/**`、`/app/banner/list`
  - 状态：已支持管理端增删改查/上下线，App端读取有效Banner
- 运营公告闭环
  - 表：`notice`
  - 接口：`/admin/notice/**`、`/app/notice/list`
  - 状态：已支持管理端增删改查/发布，App端按发布时间读取
- 系统配置闭环
  - 表：`system_config`
  - 接口：`/admin/system-config/**`、`/app/system-config/map`
  - 状态：已支持管理端增删改查、按key批量读取
- 自动化回归
  - 资产：`tests/fitness-platform.postman_collection.json`
  - CI：`.github/workflows/ci.yml`、`.github/workflows/integration.yml`
  - 状态：云端临时 MySQL/Redis/MinIO + SQL 初始化 + Newman 回归已跑通

## 未实现
- 订单明细拆分能力未使用
  - 表：`order_item`
  - 缺口：当前链路可跑，但未充分使用“多明细订单”能力

## 计划延期（V2 明确不做）
- 第三方真实支付网关接入（微信/支付宝 SDK + 真签名验签）
  - 现状：使用 mock 回调链路验证业务一致性
  - 延期原因：学习项目优先保证业务闭环与可回归
- MQ 生产化异步链路（死信、重试、消费幂等监控）
  - 现状：核心链路先用同步/定时补偿保证可运行
  - 延期原因：当前简历阶段先做“能解释清楚”的最小可行架构
- 前端/Nginx 正式部署编排
  - 现状：后端 API 和中间件链路已可用
  - 延期原因：先收敛后端业务深度，再做部署演示

## V2边界（冻结）
- 本阶段必须保证：
  - App 端核心链路可跑通：登录 -> 计划订阅 -> 打卡 -> 预约/支付回调 -> 课程报名/退款 -> 教练申请
  - Admin 端核心运维可跑通：课程与视频管理、订单/退款/回调审计、教练申请审核
  - CI 可自动验证：编译门禁 + Integration 回归
- 本阶段不新增：
  - 新业务域（如饮食、社交、社区、问答）
  - 与简历价值弱相关的重型基础设施改造

## 后续进入 V3 的触发条件
- V2 所有“已实现”链路连续 1 周回归稳定（Integration 持续通过）。
- 先补“未实现”里价值最高的 1~2 项，再考虑扩域。
