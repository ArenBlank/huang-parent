## 5. AI 编码规范（总则）
> 目标：不盲目堆量，优先稳定、主流、可解释、可演示。

- 每次改动必须对应一个明确问题或演示目标
- 优先小步快跑：能演示即可，不做过度设计
- 新增内容必须有退出条件（成功标准），达标即停
- 不引入非必要中间件或实验性技术
- 有影响的修改必须同步更新文档 / 回归用例

## 6. AI 编码规范（前端）
- 技术栈维持：Vue 3 + Vite + Pinia + Axios + Element Plus
- 不引入多套 UI 框架，不堆新依赖
- 只补“可演示必需”的页面与交互
- 保持页面语言统一为中文
- 所有 API 统一走代理，不直接硬编码后端域名

## 7. AI 编码规范（后端）
- 技术栈维持：Spring Boot 3.x + MyBatis-Plus + MySQL + Redis + MinIO
- 只补“链路闭环”与“稳定性”相关能力
- RBAC 以资源/操作级为主，不做复杂策略引擎
- 日志与 TraceId 为必须项，但不引入完整链路追踪平台

## 8. 主流且稳定的亮点（优先保留）
- 统一登录鉴权（JWT）+ RBAC 权限边界
- 关键链路 TraceId + 耗时日志
- 操作日志审计
- 业务链路闭环（支付回调幂等 / 超时关单）
- 自动化回归（Postman + CI）

## 9. 边界规则（防止无限扩展）
- 不新增大业务
- 不引入新中间件
- 不做架构重构
- 只修“阻断 + 可演示稳定性”问题

## 10. 快速启动（本地）
- 中间件：见 `start_or_stop.txt`
- 构建公共模块（单模块运行前必须）：
  - `mvn -pl common,model -am -DskipTests install`
- 启动服务：
  - Admin：`mvn -f web/web-admin/pom.xml spring-boot:run`
  - App：`mvn -f web/web-app/pom.xml spring-boot:run`
- 前端：
  - Admin：`frontend` → `npm run dev`（5173）
  - App：`frontend-app` → `npm run dev`（5174）
