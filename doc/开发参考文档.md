# 开发参考文档

> 用途：让新的开发或 AI 会话快速理解当前项目目标、进度、边界和演进方向，避免继续围绕旧状态做判断。

## 1. 当前项目目标

- 面试展示：能讲清业务闭环与工程亮点
- 作品集展示：功能可演示、可回归、可复现
- 工程沉淀：不是一次性 Demo，而是可持续演进的工程型单体

## 2. 当前项目主题

- 运动健康管理平台
- 双端形态：`web-admin` + `web-app`
- 核心业务：训练计划、训练打卡、课程学习、教练预约、支付回调、退款、运营位、RBAC、审计

## 3. 当前阶段定位

- V2：核心业务闭环 + 自动化回归体系
- V3：并发治理、多实例部署、缓存设计、任务中心、稳定性补强

当前可视为：

- 核心业务闭环完成
- 多实例与并发治理方案完成
- 多级缓存近实时失效完成
- 任务中心与认证补强完成
- 自动化回归与双实例 smoke 已接好

## 4. 当前已完成的关键改造

### 4.1 部署与运行形态

- `web-admin` 单实例
- `web-app` 双实例
- Nginx `upstream` 轮询转发
- `X-App-Instance` 用于验证负载均衡命中

### 4.2 认证与权限

- App/Admin 统一走 JWT
- 增加 `tokenVersion` 校验
- App/Admin refresh token 能按平台续签
- RBAC 权限模型已落地到数据库和配置兜底

### 4.3 并发治理

- `@RateLimit`
- `@IdempotentSubmit`
- Redis 短锁、短幂等键、固定窗口限流
- 轻量 Redis 锁增强：`SET NX EX` 获取锁 + Lua compare-and-delete 安全释放 + typed `LockAcquireResult`
- 支付回调收敛为“Redis 削峰 + 数据库条件更新幂等兜底”
- 缓存重建增加随机退避重读，避免热点 key 同时回源
- 数据库条件更新 + 唯一索引兜底

### 4.4 多级缓存

- `Caffeine + Redis + Redis Pub/Sub`
- 仅静态低频数据进入本地缓存
- 事务提交后统一执行共享缓存失效与本地缓存广播失效

### 4.5 运维与补偿

- 任务中心接口已接入
- `task_run_log` 已落库
- `PAYMENT_COMPENSATE`、`BOOKING_TIMEOUT_CLOSE` 已接入

### 4.6 可观测性

- `traceId + userId + instanceId`
- 操作日志
- 支付回调审计
- 退款审计

### 4.7 鉴权缓存补强

- Admin 鉴权热路径已切到 Redis RBAC 权限视图缓存
- 通过 `AdminAuthView` 聚合角色、权限和课程分类范围
- 通过领域事件在事务提交后定向驱逐受影响用户缓存
- App 鉴权已补纯 Redis L2 缓存，仅缓存 `status + tokenVersion`

### 4.8 守卫降级与任务互斥

- `@RateLimit` 在 Redis 异常时按 `failOpen` 优雅放行
- `@IdempotentSubmit` 在 Redis 异常时强制 `fail-close`
- 定时任务已接入 `@DistributedTaskLock`
- 支付补偿与订单超时任务使用动态 TTL 执行锁

## 6. 当前技术边界

- 不引入微服务拆分
- 不引入 MQ、Seata、Gateway、Nacos
- 不把订单、支付、库存、预约状态放进本地缓存
- 不把 Redis 当作最终正确性来源
- 不为了堆简历名词引入无落地支撑的框架

## 7. AI / 开发改动规范

### 7.1 总则

- 每次改动必须对应明确问题或演示目标
- 优先小步快跑，保证可验证
- 新增能力必须有退出条件
- 改代码后同步更新文档与验证入口

### 7.2 后端规则

- 技术栈保持：Spring Boot 3.x + MyBatis-Plus + MySQL + Redis + Caffeine + MinIO
- 并发治理优先复用现有三层策略
- 强一致链路优先数据库兜底
- 缓存改动必须明确“哪些数据能缓存、哪些不能”
- Redis 异常时必须明确 `fail-open` 还是 `fail-close`，不能默默吞掉守卫失败

### 7.3 文档规则

- README 用于 GitHub 首页总览
- `doc/工程技术亮点汇总.md` 用于项目整体技术概述
- `doc/单体双实例与Redis并发落地说明.md` 用于并发与缓存设计说明
- `doc/简历项目亮点（真实增强版）.md` 用于简历与面试表述

## 8. 推荐继续演进的方向

### 8.1 值得继续做

- 压测数据沉淀
- 指标化可观测性
- 更完整的 CI smoke 与回归报告
- README / 文档持续保持和当前代码一致

### 8.2 不建议当前阶段做

- 微服务化
- 引入新的中间件栈
- 大规模 UI 或业务重构
- 为了“术语更高级”引入无落地支撑的框架

## 9. 快速启动

### 9.1 启动依赖和服务

```powershell
powershell -ExecutionPolicy Bypass -File start-all.ps1
```

### 9.2 重置测试数据

```powershell
powershell -ExecutionPolicy Bypass -File tests/reset-test-data.ps1
```

### 9.3 常用命令

- 双实例验证：
  - `powershell -ExecutionPolicy Bypass -File tests/check-dual-app-routing.ps1`
- 并发验证：
  - `powershell -ExecutionPolicy Bypass -File tests/invoke-concurrent-requests.ps1`
- 核心回归：
  - `newman run tests/fitness-platform-core.postman_collection.json -e tests/local.postman_environment.json`
- 全量回归：
  - `newman run tests/fitness-platform-full.postman_collection.json -e tests/local.postman_environment.json`
