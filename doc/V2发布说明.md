# V2发布说明

## 1. 版本定位
V2 是当前项目的稳定基线版本，目标是把“健身平台核心业务闭环 + 自动化回归 + 基础工程治理”收敛到可演示、可回归、可继续迭代的状态。

## 2. 已完成业务闭环

### 2.1 用户端
- 用户登录、JWT 鉴权
- 训练计划订阅
- 训练打卡与周统计
- 教练预约创建
- 模拟支付回调与支付幂等
- 超时关单
- 课程报名、支付、退款、报名记录查询
- 个人资料查询、修改、改密
- Banner、公告、系统配置读取

### 2.2 管理端
- 课程创建、发布、排期、更新
- 视频上传、素材管理、训练计划项绑定/解绑视频
- Banner、公告、系统配置管理
- 教练申请审核
- 预约订单、课程订单、退款审计、支付回调审计查询
- 操作日志查询
- 用户、角色、用户角色关系管理

## 3. 工程技术亮点

### 3.1 状态机与一致性
- 预约链路：`WAIT_PAY -> PAID -> SERVING -> COMPLETED -> CANCELED`
- 订单链路：`UNPAID -> PAID -> CLOSED -> REFUNDED`
- 支付回调做了幂等控制，避免重复通知重复入账
- 超时关单任务保证未支付单据自动关闭

### 3.2 鉴权与权限边界
- App/Admin 双端 JWT 鉴权隔离
- Admin 侧新增最小 RBAC：
  - `ADMIN`
  - `OPS_ADMIN`
  - `AUDIT_ADMIN`
- 通过 `@RequireAdminRole` 对高风险管理接口做角色约束

### 3.3 审计与可追踪
- 关键业务写入操作日志
- 支付回调审计、退款审计可在管理端查询
- 教练申请审核过程已可通过日志回放关键操作

### 3.4 自动化回归
- 保留两套 Postman 集合：
  - `tests/fitness-platform-core.postman_collection.json`
  - `tests/fitness-platform-full.postman_collection.json`
- Core 回归用于快速校验核心链路
- Full 回归用于发版前校验完整业务与管理操作
- GitHub Actions 已打通：
  - `CI / build`
  - `CI / api-core-regression`
  - `Integration / api-regression`

### 3.5 环境与部署基础
- 已支持 `dev / test / prod` 多环境配置
- 已提供 Nginx 反向代理模板
- 已补部署说明文档，明确环境变量与启停方式

## 4. 当前验证结果
- Maven 编译通过
- Core 回归通过
- Full 回归通过
- GitHub Actions 三条检查全绿

## 5. 已知限制
- 支付平台仍是模拟回调，未接真实微信/支付宝 SDK
- RBAC 目前是“最小可用版本”，还不是细粒度资源权限模型
- 日志更偏审计用途，监控、指标、链路追踪尚未完整接入
- 仍缺标准化前端工程与完整部署自动化

## 6. V3建议方向
- 接入真实支付适配层，抽象签名校验与回调处理
- 强化 RBAC，细化到运营/审核/超管职责分离
- 增加 traceId、耗时日志、监控指标
- 补标准化发布脚本与服务器部署流程
- 视需要接入前端管理台或用户端页面
